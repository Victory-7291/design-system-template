# AI-Native Design System Template

> **Code as Design — a production-ready design system template where Tailwind CSS is the single source of truth for design tokens, and component sources are the core assets.**
> Ships with 53 shadcn/ui primitives, an editorial content kit, Google Stitch `DESIGN.md`, Storybook 8 with accessibility auditing, Playwright dual-viewport visual regression, and W3C DTCG as a bidirectional interchange format.

## 1. Design Philosophy: Code as Design

- **CSS is the source of truth for design tokens.** Every token — foundation measures, semantic layers (light, fixed-dark, dark overrides) and Tailwind v4 `@theme` bindings — is hand-maintained in [`packages/design-tokens/styles/tokens.css`](packages/design-tokens/styles/tokens.css). Writing CSS *is* the design act; there is no token compilation step and therefore no source/artifact drift.
- **Component sources are core assets.** The component packages (`@design-system/ui`, `@design-system/content-ui`) are maintained as TypeScript sources and compiled to `dist/` (`tsc`) for distribution.
- **DTCG is an interchange format, not a source.** Export your tokens to W3C DTCG JSON for Figma (Tokens Studio), Swift, Kotlin or React Native; import externally-authored DTCG files back into CSS variable blocks.
- **Pre-generated utility stylesheets, per package.** Tailwind utility rules referenced by the component className strings are pre-generated by this repo's build — `packages/ui/styles.css`, `packages/content-ui/styles.css`, plus the legacy union `packages/design-tokens/styles/utilities.css` behind `index.css`. Bundler dev servers cannot scan package sources, so consumers import these plain stylesheets instead.

## 3. Commands

```bash
bun install                # Install dependencies

bun run build              # Generate per-package styles.css + compile ui/content-ui dist
bun run generate:styles    # Regenerate the three stylesheets only (required after className changes)
bun run typecheck          # ui + content-ui type checking (tsc --noEmit)

bun run tokens:export      # tokens.css → dtcg/*.tokens.json (W3C DTCG interchange)
bun run tokens:import -- <file.json> [out.css]   # DTCG JSON → CSS variable blocks

bun run lint:design        # DESIGN.md schema & WCAG contrast audit (@google/design.md)
bun run storybook          # Storybook sandbox (port 6006)
bun run storybook:build    # Storybook static build
bun run test:visual        # Playwright dual-viewport visual regression
bun run test:visual:update # Update golden snapshots after intentional changes
```

## 4. Styling Integration (consumers)

Import the token package once in your global stylesheet, before the Tailwind engine, plus the stylesheets of the component packages you use:

```css
@layer theme, base, components, utilities; /* lock cascade layer order */
@import "@design-system/tokens/styles/tokens.css";
@import "tailwindcss";
@import "@design-system/ui/styles.css";          /* interaction primitives */
/* @import "@design-system/content-ui/styles.css"; — add if the editorial kit is installed */

body {
  background-color: var(--color-surface-canvas);
  color: var(--color-text-primary);
  font-family: var(--font-sans);
  min-height: 100dvh;
}
```

- `tokens.css` carries the variables + `@theme` bindings; each component package ships its own pre-generated `styles.css` covering every utility class its components use (including responsive/`data-*` variants and tw-animate motion classes).
- Prefer `@design-system/tokens/styles/index.css` (tokens + a pre-generated union of both packages' utilities) if you want a single import for everything instead.
- After changing component classNames in this repo, run `bun run generate:styles` and publish — consumers just upgrade the package.
- Fixed dark surfaces (inverse CTA panels, dark banners) use the `-dark` utilities: `bg-surface-canvas-dark`, `text-text-secondary-dark`, …

## 5. Token Interchange (DTCG)

`tokens.css` is the source of truth; DTCG files under `dtcg/` are generated exports for design tools and platform teams:

```bash
bun run tokens:export                     # tokens.css → dtcg/foundation.tokens.json + dtcg/semantic.tokens.json
bun run tokens:import -- <file.json> out.css   # external DTCG → CSS variable blocks
```

The exported files follow the W3C Design Tokens Community Group format and can be imported into Figma (Tokens Studio) or translated to Swift / Kotlin / React Native themes.

## 6. Quality Gates

- **Types**: `bun run typecheck` (ui + content-ui, `tsc --noEmit`)
- **Accessibility**: Storybook `@storybook/addon-a11y` (live axe-core scanning, WCAG AA / APCA)
- **Visual regression**: `bun run test:visual` (Playwright snapshots at 1280 and 390 widths)
- **Design spec audit**: `bun run lint:design` (`@google/design.md` CLI validates `DESIGN.md`)
- **Versioning**: Changesets + GitHub Actions (`.github/workflows` not included in this template — wire up `changesets/action` when you enable publishing)
